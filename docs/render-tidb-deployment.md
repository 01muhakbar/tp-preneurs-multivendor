# Render + TiDB Cloud Deployment Handoff

This app is MySQL-compatible through Sequelize and `mysql2`, so TiDB Cloud Starter is the preferred free/low-cost production database path before considering a PostgreSQL migration.

## 1. Create The TiDB Database

1. Sign in to TiDB Cloud.
2. Create a Starter or Essential instance.
3. Choose the closest region available to the app host. For the current `render.yaml`, Render is set to `singapore`, so choose an Asia/Singapore-adjacent TiDB region when available.
4. Open the instance connection panel and choose a MySQL-compatible direct connection.
5. Copy the host, port, database name, username, and password.

TiDB Cloud documents Starter/Essential direct connections as standard MySQL protocol connections, and the repo's runtime/migration code already supports this through `DATABASE_URL`.

## 2. Build `DATABASE_URL`

Use this shape:

```text
mysql://USERNAME:PASSWORD@HOST:PORT/DATABASE_NAME
```

If the username contains a TiDB tenant or cluster prefix, keep it exactly as TiDB shows it. URL-encode special characters in username/password, especially `@`, `:`, `/`, `#`, `?`, and `%`.

Example shape only:

```text
mysql://4abc123.root:encoded_password@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/test
```

## 3. Render Environment Values

During Render Blueprint creation, `render.yaml` prompts for these values:

```text
DATABASE_URL=mysql://USERNAME:PASSWORD@HOST:PORT/DATABASE_NAME
CLIENT_URL=https://your-render-service.onrender.com
CORS_ORIGIN=https://your-render-service.onrender.com
PUBLIC_BASE_URL=https://your-render-service.onrender.com
```

The Blueprint already sets:

```text
NODE_ENV=production
DB_SYNC=false
DB_SSL=true
DB_SSL_REJECT_UNAUTHORIZED=true
AUTH_COOKIE_NAME=tp_auth
COOKIE_SECURE=true
UPLOAD_DIR=uploads
```

`JWT_SECRET` is generated by Render from the Blueprint.

## 4. First Deploy Flow

1. Push the repo to GitHub with `Dockerfile`, `.dockerignore`, `render.yaml`, and the production docs committed.
2. In Render, create a new Blueprint from the GitHub repo.
3. Fill the prompted env values.
4. Let Render build the Docker image.
5. Render runs `pnpm -F server migrate` before starting the service.
6. Confirm `/api/health` returns JSON with `ok: true`.

## 5. Local Verification Before Push

Run:

```bash
pnpm.cmd build
pnpm.cmd -F server migrate --dry-run
```

With a real production `DATABASE_URL`, verify against TiDB before public launch:

```bash
pnpm.cmd -F server migrate --print-config
pnpm.cmd -F server migrate
```

Do not set `DB_SYNC=true` in production.

## 6. Known Temporary Limitation

`UPLOAD_DIR=uploads` is fine for a first staging deployment, but local container uploads are not durable on Render free web services. Move production uploads to object storage, such as Cloudflare R2, before relying on uploaded product/staff/branding images.
