# Production Deployment Checklist

Use this as the final environment checklist before public deployment. Backend remains the source of truth; do not replace missing backend config with client-side fallbacks.

## Required Environment

- `NODE_ENV=production`.
- Production database is configured with either `DATABASE_URL` or all split `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`.
- `DB_SYNC` is not `true`.
- `JWT_SECRET` is strong, unique, at least 24 characters, and not an example/dev value.
- `AUTH_COOKIE_NAME` is explicit.
- `CLIENT_URL` or `CORS_ORIGIN` uses the public HTTPS client origin. On Render single-origin deploys, the server can infer this from `RENDER_EXTERNAL_HOSTNAME`.
- `COOKIE_SECURE` is omitted or `true` for public HTTPS. `false` is only for localhost proof runs.
- `PUBLIC_BASE_URL`, `CLIENT_PUBLIC_BASE_URL`, or `STORE_PUBLIC_BASE_URL` points to the public storefront URL for hosted checkout redirects. On Render single-origin deploys, `PUBLIC_BASE_URL` can be inferred from `RENDER_EXTERNAL_HOSTNAME`.
- `UPLOAD_DIR` points to a writable persistent directory. The server serves it as `/uploads`.
- Client builds set `VITE_SERVER_ORIGIN` when uploads/API are served from a different origin than the client app.

## Render Blueprint

- `render.yaml` defines one Docker web service for single-origin deployment.
- Initial Blueprint creation prompts only for `DATABASE_URL`; `JWT_SECRET` is generated and Render origin values are inferred at runtime.
- `JWT_SECRET` is generated by Render unless you set an existing secret manually.
- Set `CLIENT_URL`, `CORS_ORIGIN`, and `PUBLIC_BASE_URL` manually only when using a custom domain or a non-Render host.
- Render free tier does not support `preDeployCommand`; `dockerCommand` runs `pnpm deploy:start`, which applies migrations first and then starts the service. Keep `DB_SYNC=false` so production schema changes come only from migrations.
- For TiDB Cloud Starter, keep `DB_SSL=true` and `DB_SSL_REJECT_UNAUTHORIZED=true`.
- Render free web services do not provide durable local uploads. Treat `UPLOAD_DIR=uploads` as staging-only until production upload storage is moved to object storage.
- See `docs/render-tidb-deployment.md` for the database setup handoff.

## Repository Readiness

- GitHub Actions `Deploy Readiness` passes before public deploy. It runs `pnpm deploy:verify`.
- Runtime cookies, temporary API dumps, local logs, and generated upload files are not tracked by git.
- Demo baseline upload assets can remain tracked only when referenced by seed/smoke scripts, such as `/uploads/products/demo.svg` and `/uploads/products/demo-kacha/*`.
- Production uploads are backed by object storage before accepting real seller/admin media. Cloudflare R2 is the preferred first target because its free tier is enough for small staging media workloads.

## Payment And Webhook

- COD can operate without external payment secrets.
- Stripe checkout becomes available only when Admin Store Settings contain valid Stripe publishable and secret keys.
- Stripe webhook sync requires a valid Stripe webhook signing secret in Admin Store Settings before `/api/store/stripe/webhook` will process events.
- Public checkout redirect base URL must be set before enabling Stripe publicly.
- `RATE_LIMIT_DISABLED` must stay unset/false in production unless an upstream WAF or gateway already enforces equivalent limits.
- `RATE_LIMIT_NON_PRODUCTION_MULTIPLIER` is for local/test only; production always uses the configured route limits.

## Security Smoke

- Auth/login rate limit smoke remains green.
- Checkout/cart/order/payment smoke remains green.
- `pnpm qa:e2e:truth` remains green after deployment config changes.
- Public image paths under `/uploads` load from the same persistent upload directory used by admin/seller uploads.
